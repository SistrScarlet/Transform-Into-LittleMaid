# TILM 1.21.1 移植計画

## 概要

Transform-Into-LittleMaid (TILM) を Minecraft 1.20.1 (5.0.0) から 1.21.1 へ移植する。
LMML 1.21.1 (9.0.0-beta.1) / LMRB 1.21.1 (9.0.0-beta.3) の移植作業を参考にする。

参照:
- `LittleMaidModelLoader-Architectury/docs/research/2026-06-06_lmml-1.21.1-migration-lessons.md` (最重要 — API チートシート・NeoForge テンプレート)
- `LittleMaidReBirth-Architectury/docs/plan/2026-06-06_lmrb-1.21.1-migration.md` (フェーズ構成の参考)

## TILM の依存関係の特徴

TILM は **LMML にのみ依存し、LMRB には依存していない**(`build.gradle` の `mods/` フォルダに LMML jar のみ配置、import も `net.sistr.littlemaidmodelloader.*` のみ)。
DataComponents 化・Enchantment データ駆動化など LMRB 特有の大工事には巻き込まれない。ソース規模も 20 ファイルと小規模。よって LMRB のような大規模計画にはせず、LMML 移植フェーズを踏襲した軽量版で進める。

## 確定方針

| 項目 | 決定 |
|------|------|
| ターゲット MC | 1.21.1 ピン留め |
| プラットフォーム | fabric + neoforge (forge は切る) |
| ベースブランチ | `1.20` |
| 移植先ブランチ | `1.21.1` |
| バージョン | 未定(LMML/LMRBが `9.0.0` 系なので揃えるかは要検討。まずは動作優先) |
| 依存 jar | LMML 1.21.1 (9.0.0 系最新ビルド) を `mods/` に配置 |

## 作業フェーズ

### フェーズ 0: 依存 jar 確保

- LMML 1.21.1 の fabric/neoforge jar をビルドして `common/mods/`, `fabric/mods/`, `neoforge/mods/` に配置

### フェーズ 1: ビルド環境セットアップ

- `1.20` から `1.21.1` ブランチを作成
- `gradle.properties` 更新 (上表バージョン)
- `settings.gradle`: `include("forge")` → `include("neoforge")` (forge は残置、Gradle 対象からのみ除外)
- `gradle-wrapper.properties` を 8.8 に更新
- ルート `build.gradle` の `options.release = 17` → `21`
- `neoforge/` モジュール新規作成 (LMML フェーズ1と同じ構成をコピー・書き換え)

### フェーズ 2: バニラ / LMML API 追従

機械的置換:
- `new Identifier(MODID, "...")` → `Identifier.of(MODID, "...")` — `TransformLittleMaidPacket.java`, `RequestSyncMultiModelPacket.java`, `LittleMaidPlayerRenderer.java` (NULL_TEXTURE)
- `EquipmentSlot.Type.ARMOR` 判定 → `slot.isArmorSlot()` — `MixinPlayerEntity.java` の `onEquipStack`

構造変更 (要個別確認、Explore調査結果待ち):
- `writeCustomDataToNbt` / `readCustomDataFromNbt` のシグネチャ変更 (`RegistryWrapper.WrapperLookup` 引数追加の可能性) — `MixinPlayerEntity.java`
- `PlayerEntity` コンストラクタのシグネチャ変更有無 (`onInit` Inject の引数)
- `getActiveEyeHeight` / `getMountedHeightOffset` / `getHeightOffset` が 1.21.1 で削除されているか — LMML移植lessonsでは「削除」と記載されており、LMML自身も機能ロスとしてTODO化している。TILM の `MixinPlayerEntity` はこれらを @Override / @Inject で使用しているため、削除されていれば **コンパイルエラー** になる。設計判断のエスカレーションが必要になる可能性が高い(下記「要エスカレ」参照)
- CustomPayload 化: `TransformLittleMaidPacket`, `RequestSyncMultiModelPacket` を `record implements CustomPayload` へ書き換え。LMML の `SyncMultiModelPacket` が CustomPayload 化されていれば呼び出し側もそれに合わせる
- LMML API 変更追従: `IHasMultiModel` 等のシグネチャ変更があれば実装側 (`MixinPlayerEntity`, `MultiModelCopyUtil`, `LittleMaidPlayerRenderer`) を追従

### フェーズ 3: Mixin 再検証

- `MixinEntityRenderDispatcher` (`getRenderer`, `reload`) のシグネチャ確認
- `MixinPlayerEntity` の `<init>`, `initDataTracker`, `tickMovement` 等の対象メソッド確認
- `MixinClientPlayNetworkHandler#onPlayerRespawn` のシグネチャ確認

### フェーズ 4: NeoForge プラットフォーム入口書き換え

- `TransformIntoLittleMaidModForge.java` → `TransformIntoLittleMaidModNeoForge.java` (LMML lessons のテンプレート通り、`IEventBus modBus, ModContainer container` コンストラクタへ)
- `neoforge.mods.toml` 新規作成

### フェーズ 5: 統合テスト

- `./gradlew :fabric:build :neoforge:build`
- `spotlessApply` / `checkstyleMain` / `spotbugsMain`
- 手動動作確認: 変身キー、モデル選択画面、防具装着、リスポーン時のモデル引き継ぎ、マルチプレイでの同期

## 要エスカレの可能性がある設計判断

- **getActiveEyeHeight / getMountedHeightOffset / getHeightOffset が削除されている場合の対応**: LMML/LMRB 同様に機能ロス受容(固定値化)で進めるか、`EntityAttachments` 経由で復元するか。LMML が既に同じ問題を「機能ロス」として TODO 化しているため、TILM でも同方針(受容)を基本線とするが、変身時の見た目・視点への影響度合いを見て判断する
