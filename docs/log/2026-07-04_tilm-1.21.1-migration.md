# TILM 1.21.1 移植セッション記録

## 経緯

LMML / LMRB の 1.21.1 移植作業を参考に、Transform-Into-LittleMaid (TILM) を 1.20.1 (5.0.0) から 1.21.1 (6.0.0) へ移植した。

TILM は **LMML にのみ依存し、LMRB には依存していない**(import は全て `net.sistr.littlemaidmodelloader.*`)。DataComponents 化・Enchantment データ駆動化など LMRB 特有の大工事には巻き込まれず、ソース規模も 20 ファイルと小規模だったため、LMRB のような大規模フェーズ計画は組まず、LMML の移植内容を踏襲した軽量な作業で完了した。

計画書: `docs/plan/2026-07-04_tilm-1.21.1-migration.md`
参照した LMML lessons: `LittleMaidModelLoader-Architectury/docs/research/2026-06-06_lmml-1.21.1-migration-lessons.md`

## 主要な変更点

### ビルド環境

- `gradle.properties`: minecraft_version/yarn_version/architectury_version/fabric系/cloth_config/mod_menu を LMML/LMRB の 1.21.1 系バージョンに統一。`neoforge_version`, `yarn_mappings_patch_neoforge_version` を追加
- `settings.gradle`: `include("forge")` → `include("neoforge")`(forge ディレクトリ自体は参照用に残置、Gradle 対象からのみ除外)
- `gradle-wrapper.properties`: Gradle 7.4 → 8.8
- root `build.gradle`: `dev.architectury.loom` を `1.7.435` に、`options.release` を 17 → 21 に変更
- `fabric/build.gradle`: shadow plugin を `com.github.johnrengelman.shadow:7.1.2` → `com.gradleup.shadow:8.3.3`、`classifier` → `archiveClassifier`
- `neoforge/build.gradle`, `neoforge/src/**`, `neoforge/gradle.properties` を新規作成(LMML のファイルをテンプレートに)
- `TransformIntoLittleMaidModForge.java` (forge) はそのまま残置し、`TransformIntoLittleMaidModNeoForge.java` を新規作成。NeoForge 21.1 のプラットフォーム入口シグネチャ (`IEventBus modBus, ModContainer container`) に合わせて書き直し

### バニラ API 追従

- `new Identifier(ns, path)` → `Identifier.of(ns, path)` (`TransformLittleMaidPacket`, `RequestSyncMultiModelPacket`, `LittleMaidPlayerRenderer`)
- `EquipmentSlot.Type.ARMOR` 判定 → `slot.isArmorSlot()` (`MixinPlayerEntity#onEquipStack`)
- `initDataTracker()` (引数なし) → `initDataTracker(DataTracker.Builder builder)`。`this.dataTracker.startTracking(...)` → `builder.add(...)`
- CustomPayload 化: `TransformLittleMaidPacket`, `RequestSyncMultiModelPacket` を `record implements CustomPayload` + `PacketCodec` に書き換え。`Networking.init()` の `registerReceiver` に CODEC 引数を追加
- LMML 側 `SyncMultiModelPacket` の新 API (`sendS2CPacket(Entity, IHasMultiModel)`) に追従。旧 `SyncMultiModelPacket.ID` / `createS2CPacket` は廃止されていた

## 機能ロス(1.21.1 の破壊的変更に伴うもの)

- **`getDimensions(EntityPose)` / `getEyeHeight(EntityPose)`(旧 `getActiveEyeHeight`)**: Entity/LivingEntity 側で最終的な実装が確定し、`PlayerEntity` 自身はこれらのメソッドをオーバーライドしなくなった。Mixin の `@Inject` は「ターゲットクラス自身がそのメソッドを保持している」ことを前提とするため、対象を解決できず remap 時に `Cannot remap getDimensions because it does not exists in any of the targets [PlayerEntity]` という警告が出て機能しない。**変身時のモデルサイズに応じた当たり判定・視点の高さ調整が失われた**。LMML も同一制約に直面し `MultiModelEntity` 側で「動的 dimensions/eye height は EntityAttachments ベースに移行、当面は固定値運用」として機能ロス受容している。TILM は PlayerEntity(バニラ既存クラス)にしか Mixin できず、LMML のような `EntityType.Builder` での固定値運用の代替も取れないため、追加の対応方針は現状ない
- **`Entity#getMountedHeightOffset` の廃止**: `getPassengerRidingPos(Entity passenger)` のオーバーライドで代替した(このメソッドは Entity 自体が保持しているため `@Override` は問題なく機能する)。`getPos().add(0, model.getMountedYOffset(getCaps()), 0)` という簡易実装で、X/Z のズレは考慮していない
- **`Entity#getHeightOffset` の廃止**: 代替 API が存在しないため機能ロス受容。TODO.md に記録

## トラブルシューティング: `neoForge()` が dependencies ハンドラに見つからない

ビルド環境構築時、`neoforge/build.gradle` の `dependencies { neoForge "net.neoforged:neoforge:..." }` で以下のエラーが発生:

```
Could not find method neoForge() for arguments [net.neoforged:neoforge:21.1.233]
  on object of type org.gradle.api.internal.artifacts.dsl.dependencies.DefaultDependencyHandler.
```

LMML/LMRB の `neoforge/build.gradle` と1文字単位で diff しても差異がなく、`architectury { neoForge() }` ブロック自体は例外なく完了する(デバッグ println で確認済み)ため、原因究明に時間を要した。

architectury-plugin (`ArchitecturyPluginExtension.kt`) のソースを読むと、`neoForge()` は `loader(ModLoader.NEOFORGE, action)` → `transform(...)` を呼ぶだけで、**dependencies ハンドラへの `neoForge` 拡張メソッド登録には一切関与しない**。この拡張メソッドは Architectury Loom (`dev.architectury.loom`) 側が提供しており、Loom がそのサブプロジェクトを NeoForge プラットフォームだと判定した場合にのみ有効になる。

判定条件は architectury-loom リポジトリ (`dev/1.7` ブランチ) のテストプロジェクト `src/test/resources/projects/neoforge/1210/gradle.properties` で判明:

```properties
loom.platform = neoforge
```

**サブプロジェクト直下の `gradle.properties` にこの1行が必要**。LMML/LMRB の `neoforge/gradle.properties` には既にこの設定があったが、TILM のディレクトリ作成時に見落としていた(この設定ファイル自体の存在に気づいていなかった)。追加したところ即座に解決。

### 教訓

- `architectury { neoForge() }` のようなプラットフォーム宣言 DSL と、`loom.platform` プロパティは**別の仕組み**であり、両方揃って初めて NeoForge サブプロジェクトとして機能する
- 新規モジュールをテンプレートからコピーする際は、`build.gradle` だけでなく**そのディレクトリ直下の `gradle.properties` の有無**も必ず確認する(隠れた設定ファイルを見落としやすい)
- 原因不明のエラーは、まず類似プロジェクト(LMML/LMRB)との `diff` を取ってファイル内容の一致を確認し、それでも解決しない場合はプラグイン自体のソース(GitHub)を読むのが確実。今回は `gh api repos/architectury/architectury-plugin/...` や `gh api repos/architectury/architectury-loom/...` で実装・テストプロジェクトを直接確認して解決した
